# 双轴连续随机摆动（已按用户要求停止）

2026-10-13。用户将固定2.5秒动作改为“动作大一点、横纵一起转、不要停、随意摆动”，已实际实现并运行，随后用户明确“停吧”，后台已停止并退出。

## 控制范围

- 水平PA8/TIM1_CH1，俯仰PB0/TIM3_CH3，两路1MHz计数、50Hz。
- 水平1300–1700us、俯仰1350–1650us的伪随机目标；每10ms最多变化1us，缓慢移动，不直接跳到新目标。
- GIMBAL_RUN只在就绪且两路已停止时显式启动；GIMBAL_KEEPALIVE只续期正在运行的mode4，不启动已停/重启的主控。
- 续期中断3000ms后TIM2中断将两路PWM置0。主机程序不自动重连或重新启动，控制失败则发送STOP并退出。
- 保留固定动作接口与原ToF/超声/三屏/声光/USER；电机运动指令仍禁用，驱动电池断开。

## 本轮证据

- 备份当前旧程序，实际烧录并逐字节读回通过，SHA见flash-verification.json。
- 真实生产随机模式函数的范围、限速、续期期限与计时绕回主机检查通过；未做实物断通信超时验收，不将主机测试称完整失联闭环。
- 用户确认横纵都在持续摆动、无异常，并要求继续。后台连续记录326次，约3分15秒，主控计时和启动次数未出现重置迹象。
- 用户要求停止后，写stop-request.flag，后台发GIMBAL_STOP并读回active=0、yaw_us=0、pitch_us=0，控制进程退出。软件停止输出不等于切断5V或所有舵机副本必然释放力矩。
- 两路从开发板+5V针脚供电，只证明这一实物条件下的短测。实际电压/峰值电流、长时运行、独立整车电源和相机取流/视觉/运动并发未验收。

## 停止和恢复

- 当前build/r1_gimbal_continuous/stop-request.flag保留，run_gimbal_random.py拒绝启动；不得自动清除或重新运行。
- 恢复需用户明确要求，确认物理准备后才移除停止标记并启动。
- 运行期间出现卡住、持续抖动、线拉紧、发热或重启，应停止并拔USB。
- 串口测试、烧录、调试器halt前，先停止持续控制，确认两路0和进程退出；不在舵机持续活动时暂停主控。
