# 巡迹任务代码怎么读

本模块是待实车验收的自动循迹实现。地面许可仍关闭，整理代码不表示已能沿真实胶带行驶。

- `line_task.c`：只计算状态和左右轮请求，可在电脑上用受控输入测试，不访问硬件。
- `line_task_runtime.c`：接收P7/P9命令、读取新数据、检查许可和心跳，再把允许的请求交给已有驱动层。
- `line_task.h`：状态、输入、配置及接口；状态/原因的枚举数值同时用于手机协议，不能重排。

先从`lt_start → lt_step → lt_stop`读核心，再从`task_command → line_task_poll`读适配层。原始数据来自`line_tracking_task_input`，实际运动请求进入`remote_drive_task_set`，并不在算法里直接写电机寄存器。

启动必须有显式配置、完整标定、有效输入及板端许可。启动保持零请求，等下一组完整的新模拟/数字样本才计算纠偏。白色位图中1表示地面，0表示黑线。

流程是：检查许可与新鲜度 → 确认完整新样本 → 判断单线/分叉/转向 → 计算限幅纠偏 → 适配器提交请求。丢线、过期、时限或执行拒绝会进入停止路径。读取状态不续租，只有专门心跳延长500毫秒任务租约。

本轮将核心和命令配置的范围检查共用`lt_config_valid`，配置与16值标定共用有界数字解析；保持原协议、PD参数、时序门槛和地面许可。格式由本目录`.clang-format`约束；格式化工具不是构建依赖。

以下复杂性有明确用途，不能为了短代码删掉：半新帧拒收、防计时回绕、分叉多帧确认、转向超时、有效数据检查、范围保护和独立的停止通路。
