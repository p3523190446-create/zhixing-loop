# R1：接收辅助视觉，保留独立测距预警

此固件从已运行的 `r1_distance_guard` 分出，只增加USART1接收与回传。测距、PD0蓝灯、PD1红灯、PD2绿灯、PD3蜂鸣器的逻辑不改；没有舵机或电机控制。

## 接口依据

以本地原厂 `CH32V307VCT6-R1.SchDoc` 为准：J2为6×2排针，9/10脚连接RX_OUT/TX1，11/12脚连接TX_OUT/RX1；主控TX1为PA9，RX1为PA10。WCH-Link辅助芯片的UART3是调试器侧串口，并不代表主控使用USART3。

开发板USB口朝上时，J2最上面两排分别为 `RX1 ↔ TX_0`、`TX1 ↔ RX_0`。用户已确认两排各有黑色跳帽。其余跳帽保留原状。串口参数115200、8数据位、无校验、1停止位。

旧参考PDF中的14脚J2图与此12脚版本不同，不用其脚号指导当前板接线。

## 数据协议

- `HELLO\n` → `ZXR,V1\n`，清除当前目标并重开帧序号会话。
- `PING\n` → `PONG\n`。
- `V1,seq,cls,score,cx,cy*XX\n` → `ACK,seq,cls,score,cx,cy\n`。
- `XX`是星号之前ASCII字节的CRC8（多项式0x07、初值0）；大写十六进制。
- 类别0–79使用COCO编号；255表示无目标，此时分数与坐标必须为0。
- 分数、中心位置乘1000后取整数，范围0–1000。坐标不是厘米距离。
- 错误校验、非法范围、重复或倒退帧号拒绝；超长行丢弃，在换行后恢复。
- 超过1000毫秒没有新有效帧，清除目标有效标志和类别。此标志尚未参与运动控制。
- `STATUS\n`返回在线计时、测距和视觉状态，用于避免暂停主控后再测试串口。

## 构建与验证

构建：运行 `tools/build_r1_vision_bridge.py`。工具只编译，不下载。

实物：`tools/flash_r1_vision_bridge.py COM5`，COM5须按当前设备重新确认。该脚本先备份256KB应用区并核对原预警固件，再下载、比较Flash各段并测试串口。测试失败会尝试恢复原预警固件，结果写入 `build/r1_vision_bridge/flash-uart-verification.json`。本次测试包含合成通信包，仅验证协议，不能作为真实识别证据。

真实手机链路使用 `phone_vision/bridge_ch32.py --port COM5 --duration 20`。手机须打开「知行回路视觉」并保持USB，电脑也保持连接开发板。只转发真实新帧，每帧选择模型分数最高的一个目标；结束时清除目标。它依赖电脑，不是独立车载通信。

下一步以真实帧与CH32回执为验收；没有新帧、串口超时、手机重启则停在该层，不接入运动。左右位置实物验证由用户明确跳过，保持未验证。
