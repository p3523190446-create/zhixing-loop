# 分级启动与权限框架（准备版）

依据2026-10-13用户请求编写，MCU语法编译及编译期常量场景检查通过，仍须接入主循环/命令入口并上板验收。当前运行固件仍r1_gimbal_wide。本文件不是车载功能已完成证明。

| 阶段 | 软件允许做什么 | 进入条件 |
|---|---|---|
| 0 安全待机 | 启动传感器、串口与记录；舵机PWM及轮子运动许可为零 | 上电默认 |
| 1 通信就绪 | 状态读取、错误记录 | 三条通过格式/序号/期限/授权校验的链路消息 |
| 2 云台就绪 | 接受用户明确开启后的云台操作 | 新鲜链路、舵机供电已验证、允许动作的运行配置 |
| 3 小车就绪 | CH32审核通过后允许车辆运动 | 独立整车供电已验证、传感器/距离/驱动反馈新鲜且正常、用户明确开启 |
| 故障 | 撤销运动许可 | 失联、状态无效、供电资格撤销、故障 |

通信就绪不会自动归中或启动舵机，恢复通信不会自行恢复先前动作。记录/显示属于后台工作，不能替代停止路径。

三种配置：手机OTG诊断永久拒绝云台/电机许可；电脑台架可在已验证舵机供电下开启云台，拒绝整车移动；车载独立电源配置可在各自条件合格后明确开启。默认所有供电资格false，USB枚举成功或电脑静态短测不自动把它变true。

`startup_gate.h`为CH32侧纯逻辑准备模块，不占新GPIO或定时器；应由主控完成指令合法性检查后调用。主循环tick撤销许可时，需要实际执行servo_probe_stop与电机停止；当前这些接口绑定尚未完成，不能只读取permit字段就声称实物停机已通过。建议后续加入独立停止路径、事件序号及导出，保持CH32最终控制权。

## 电源边界

停止PWM不切断舵机红线+5V。当前两只舵机挂在开发板+5V，手机OTG负载能力未验证。分级程序无法消除线路过载/电压下降，电源部分应在实际供电核验后决定独立5V或受控电源开关，不默认用户已经有这些部件。SG90官方页面给出约4.8V供电，但不提供本件实测电流或手机承载结论：[TowerPro SG90](https://towerpro.com.tw/product/sg90-analog/)。

下一步先完成当前双舵机电源断开与连接时的通信对照，再完善供电及接入框架。任何反复重启、掉电、卡住或线拉紧即停止运行。框架的失联、过期数据、恢复不自启及物理停车尚待测试，不称安全闭环完成。

## 本次验证范围

`compile_scenarios.c`以真实MCU编译器O2常量传播检查：上电零许可、三消息预热、手机OTG诊断禁止动作、未确认供电禁止动作、台架禁止车轮运动、距离阻挡及传感器/驱动过期撤销车轮许可、失联撤销两类许可、恢复不自动动作、显式停止、故障及无效配置禁止动作、32位时间回绕。失败条件保留时由编译器error属性拒绝编译。这是代码规则检查，不是目标芯片执行或物理断线试验。证据output/staged_startup/prepared-status.json。
