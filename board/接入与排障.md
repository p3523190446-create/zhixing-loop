## 2. 五个板级函数的约定

| 函数 | 必须做到 | 常见错误 |
| --- | --- | --- |
| `board_init` | 初始化时钟、GPIO 和总线；返回前输出处于已知关闭/禁止运动状态 | 上电瞬间 GPIO 浮空，输出误动作 |
| `board_millis` | 返回单调前进的 uint32 毫秒计数；确保读计数一致 | 用循环次数当毫秒；主循环阻塞导致时间停住 |
| `board_poll_distance` | 快速返回；只消费一次新测量；总线操作/等待有时间上限 | 死等数据、重复提交缓存、把厘米直接当毫米 |
| `board_write_outputs` | 把五个逻辑量映射到真实极性；一次决策后统一写 | 低电平亮灯写反；把无源蜂鸣器布尔开关当音频波形 |
| `board_delay_ms` | 延时不破坏毫秒时钟；最终验证实测循环周期 | 忙等拖慢采样而仍声称每 10 ms 刷新 |

无源蜂鸣器通常需要相应频率的驱动信号，`output.buzzer` 只表达“此刻应发声”。有源/无源、驱动能力和供电以到货资料为准。当前 `motion_allowed` 未接电机，不新增实际电机输出。

## 3. 传感器读数映射表

| 实际观测 | `available` | `valid` | `distance_mm` | 说明 |
| --- | --- | --- | --- | --- |
| 本次有全新且有效结果 | true | true | 手册单位换算后的毫米 | 含状态码/量程校验 |
| 一次明确的通信/校验/设备错误 | true | false | 0（会被忽略） | 另保留驱动错误原因日志 |
| 测量进行中，没有新结果 | false | false | 0（会被忽略） | 让主循环继续，超时由 guard 判断 |
| “无目标”或量程外 | 待依据手册决定 | 待依据手册决定 | 不猜 | 不自动把它解释成远处安全 |

距离为 0 且 `valid=true` 会被核心判断为危险；驱动若认为 0 表示错误，应显式返回 `valid=false`。先保留原始状态码，再解释距离。驱动持续返回“正在等待”也会在无有效数据达到 300 ms 后进入故障（演示初值）。

下一步：各取得一条有效、等待、错误、无目标原始记录。停止条件：这四种语义没有分清前，不通过改大超时、屏蔽错误来“修复”故障灯。

## 4. 逐级接入，失败退回上一级

| 阶段 | 操作/交付 | 通过依据 | 停止条件 |
| --- | --- | --- | --- |
| S1 | 从官方例程复制干净工程，下载 LED 与时钟程序 | 能重新编译下载；LED 与秒表观察一致 | 下载失败先查线、设备识别、板型、供电 |
| S2a | 只读一个传感器并输出原始值 | 实际远近变化对应日志；错误可解释 | 固定值、乱码、偶发卡死先查驱动 |
| S2b | 单独控制三色灯与蜂鸣器 | 每个输出方向正确，供电稳定 | 同时开启复位则先查供电/驱动 |
| S3 | A 工程加入 guard.c、app.c 与 A 入口 | 真实移动物体得到四态与恢复 | 状态不符先回放原始输入定位 |
| S3-B | 选择 B 入口并加入 fusion.c/contact.c | 按下、松开抖动、故障叠加均有记录 | 不可与 A 的 main/app_tick 双重写输出 |
| S4 | 功能冻结，完成重复测试与材料 | 实物、代码、图纸、视频对应同版本 | 有失败先修复/回退，不先写“全部通过” |

核心源文件用 C99 编译；只添加所选方案需要的文件，不把 `tests/`、`sim/` 或两个 `main` 一起加入 MCU 工程。`src/trace.c` 是电脑回放辅助，不是传感器驱动。C 档算法尚需重订完整阈值及测速失效策略；不能只改危险阈值而破坏 `danger_on < danger_off < caution_on < caution_off`。

## 5. 最小日志与定位法

串口诊断可记录 `time_ms,available,valid,distance_mm,state,fault`，另记原始状态码。回放工具只接受前四列；不要将附加列直接喂给它。日志发送本身也必须有边界，过多串口输出可能改变循环时序。记录改动前后的实测循环周期。

先比较同一条输入在主机回放与板上状态是否一致：一致而物理灯错，查输出映射；不一致，查版本/单位/时间/编译配置；输入本身不随物体变化，回到传感器层。每轮只改一处，保存之前能运行的工程。

计时器回绕测试已写进主机断言，但真实 MCU 时钟来源、长时间运行和中断一致性仍需实板验证。软件检查仅在 CPU 正常运行并调用输出函数时起作用；主循环彻底卡死时，不能把这套代码声称为硬件急停。
