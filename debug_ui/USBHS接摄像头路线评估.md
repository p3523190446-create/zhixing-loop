# 不新增集线器：USBHS接摄像头路线

> 2026-10-14 最新进度：已完成P6真实描述符读取和JPEG取帧，合并固件r1_usbhs_camera_bridge已烧入回读；电脑P9已连续读出三张完整JPEG，并确认状态回复与相机停止。统一手机0.7已安装回读，P7手机视频+云台联合实测仍待验。测距SCL/SDA已在新固件改为PB14/PB15，此分配已按用户改公排针要求更新为J4 PD14/PD15，新固件烧入回读通过、实物迁线待验，不再把测距接回PB6/PB7。当前接法见「车载接线-0.7-P6相机-P7手机.md」，证据output/onboard_dashboard/usbhs-camera-route-status.json。以下为先前识别实验准备阶段，不能当当前接线指令。

## 已核对事实

- WCH官方CH32V307资料明确USBHS支持Host/Device；本机EVT有USBHS主机枚举例程。
- 实际R1 SchDoc：P6注释USBHS，数据线接PB6/PB7，VBUS接5V_in；P7注释USBFS，P9为调试连接。三个口不是现成集线器，但P6可研究为独立摄像头主机。
- 正式固件`vl53l0x_platform.c`正使用PB6作SCL、PB7作SDA，USBHS与现有测距线路冲突。USBHS试验前要物理断开这两根线；最终集成还需重新分配测距引脚，不能同针复用。
- 外接摄像头145F:02EC经手机UVC可出MJPEG画面，这不能证明CH32已有UVC主机驱动。

## 目标结构，尚未实现视频转发

```text
摄像头USB → 现有转接头 → CH32 P6 / USBHS主机
                              ↓ 待读取UVC流、分包和转发
小手机OTG ← 数据线 ← CH32 P7 / USBFS设备
```

CH32要承担UVC协商/视频收包，并与云台指令一起向手机传输；手机也要接收新的分包协议。相机直接接手机的原UVC程序不能直接用于这个结构。

机会成本：省掉购买集线器，增加USB摄像头驱动、传输调度、数据协议和引脚调整工作。先争取低分辨率、低帧率；尚无证据能保持目前640×480/目标15fps。

## 当前准备：仅识别实验

`r1_usbhs_camera_probe`已通过MCU编译，**未烧录**。用WCH官方USBHS主机代码读取145F:02EC设备/配置描述符，报告视频接口和端点所需原始数据；不启动视频、不控制电机或舵机。

这个独立实验暂不运行正常测距/屏幕/P7通信。正式固件和0.6手机应用仍保留；测试结束恢复`r1_gimbal_usbfs_remote`。烧录程序会校验原固件、先备份全部256KiB并回读，恢复脚本仅接受确已烧入的实验固件。

第一步准备：

1. 关闭开发板、断开USB和驱动电池，舵机电源断开。
2. 只拔开发板PB6/PB7连接测距模块的两根信号线，拍照/贴标签记录原位；其余接线先保留。
3. 开发板P9接电脑、开关ON。P7空着；小手机可继续单独接电脑。
4. 相机和P6先不接，等待诊断固件烧入及回读确认后，再用现有适配转接头接摄像头→P6。

停止条件：测距PB6/PB7未隔离、接口标识不清、设备反复掉电、描述符读取失败或驱动超时。保留原始结果、恢复已验正式固件；不因识别失败反复加压、并接其他USB供电或打开电机。

后续门槛：识别目标和完整描述符 → 验证UVC端点与低负荷取帧 → 手机转发解析 → 云台/测距整合 → 同时运行验收。**识别成功不等于有视频，不承诺固定开发时长或视频帧率。**
