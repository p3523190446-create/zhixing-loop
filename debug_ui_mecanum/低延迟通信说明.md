# 低延迟通信预览

**用户最新决定：先保留方案，使用原HTTP通信。** 源码已经改为默认HTTP，仅显式`?transport=ws`启用预览；普通入口恢复1000ms轮询及200ms目标合并。以下是实时预览的实现/测试记录，不能当作当前手机的部署状态；0.5曾已集成自动长连接，后续HTTP修订是否安装另看验收。原独立预览APK保留，HTTP修订独立输出`output/onboard_dashboard/http-sync-preview/`。

用户要求低延迟。实现WebSocket长连接、最新状态推送、固定云台请求/回执和网络往返测量；不需要额外硬件或互联网服务器。当前手机USB仍由另一聊天排查，本轮未安装手机、改变USB采集或主控固件。

## 原有等待与本次修改

| 项目 | 原来 | 当前源码/预览包 |
|---|---|---|
| 小安卓从CH32收集状态 | 每约1000ms一轮 | 保持不变，仍需稳定性验收 |
| 网页获取状态 | 每1000ms HTTP请求 | WebSocket每100ms发送最新状态；旧服务/长连接失败时保留HTTP回退 |
| 摇杆目标合并发送 | 每200ms | 每50ms；一个目标在等待回执时只更新待发最新目标，不堆积历史轨迹 |
| 普通请求与停止 | 固定HTTP接口 | 固定WebSocket接口，独立停止工作队列；仍经过原USB所有者/CH32能力与租约检查 |
| 网络延迟 | 未显示 | 应用ping/pong的往返、最近60次P95，显示采样数；与主控数据年龄分开 |
| 视频 | 单独的画面请求 | 保持单独通道，不混进控制消息 |

两层1000ms周期可能叠加等待，这不是热点网络本身的实测延迟。推送10Hz也不表示传感器采样已经10Hz：旧数据仍带真实年龄，距离曲线按原采样编号去重。当前P7只读、云台写接口及车辆运动继续禁用，没有借长连接开放新主控权限。

## 结构与限制

`assets/core/realtime.js`封装浏览器长连接、心跳、回执关联、重连和延迟统计；`core/api.js`按服务能力声明选择WebSocket或HTTP。`android/RealtimeChannel.java`提供同源、有限客户端的协议处理，`LocalHttpServer`只负责接入。现有功能模块继续共用，不给iPad、手机、电脑分别复制业务逻辑。

最多3个长连接，普通命令和停止队列有容量限制。断线后未确认请求报错，不缓存到离线队列，不自动重发或恢复控制。停止工作队列可以绕过普通队列，但不能抢断正在执行的USB事务；主控租约超时/物理失联停车仍需之后实测，不能靠网络代码证明安全闭环。

长连接只承载状态和固定云台指令，摄像头开关、画质和记录仍通过原HTTP接口。主控参数预设写入尚未接入，不能说所有设置已同步到CH32。视频端到端延迟尚未实测；相机和主控同时USB、供电与手机编码负载仍是独立待验项。

- 19项协议检查通过：同一Java `RealtimeChannel`在PC JVM实际运行，使用显著标注的模拟主控数据，核握手、30次ping、状态顺序、只读拒绝、未知命令拒绝、停止与ping独立于人为延迟500ms普通任务、掩码/分片/超限拒绝及客户端限额。`output/low_latency/protocol-verification.json`。
- 15项WebKit iPad触摸模拟检查通过：真实WebSocket接入、模拟租约回执、30次快速输入合并、只读禁用、重连不自动开启、旧HTTP回退和横竖布局。`output/playwright/realtime-ui/verification.json`。这些是模拟功能，不是实物动作。
- 独立APK编译、签名通过：`output/low_latency/android-preview/zhixing-dashboard-realtime-preview.apk`，源码逐文件SHA256和构建报告在同目录。构建使用独立缓存/输出，不覆盖诊断APK；本聊天未安装预览包。
- 电脑WebKit默认系统代理下长连接握手失败；仅给这次测试浏览器配置localhost直连后通过。没有改变用户Windows代理，也没有据此认定iPad会失败。
- 手机已安装0.4的网络来源另由`output/onboard_dashboard/v04-network-provenance.json`登记：该包有预备类/文件，但未启用WebSocket入口，不能继承源码或预览包测试成果。

PC本机30次往返只能核协议工作和测量功能，不能用其亚毫秒数宣传iPad热点或CH32延迟。真实网络往返、点击至CH32确认、状态采样到屏幕、视频到屏幕须分别记录。

## 后续低延迟验收

1. 先完成USB持续通信与连接复用的实物验收；保留当前诊断版本，不叠加更高USB查询频率。
2. 单一设备诊断负责人接入预览网络模块后，iPad展开“诊断日志”，等待至少30次往返；记录中位数、P95、断联次数和主控数据年龄。测网页网络不需要开电机/舵机。
3. 主控明确开放固定写入指令并完成对应验收后，再记录“平板提交→CH32确认”的往返。**目标**先设P95≤100ms；这是目标，不是保证或已达标结论。机械转动/稳定到位另外测。
4. USB稳定后，将紧急状态与低频内容分开：距离/防撞/云台反馈优先，OLED内容、存储和诊断低频；更新采样率必须保留每字段时间和失效判断。当前没有修改该调度，不能称已10Hz采样。
5. 视频从现有640×480、15fps起核延迟和掉帧，再按实测调整清晰度与帧率。高分辨率可能增加手机处理和传输等待，不能只按像素评优。

停止条件：USB不稳、主控数据过期、命令未确认或延迟持续不达目标时，停止提高频率及实物动作，保留测量/错误；防撞判断继续在CH32本地执行，不依赖平板、热点或视频及时性。
