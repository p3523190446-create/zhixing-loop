# 车载调试台0.5：云台和摄像头

## 当前交付

- 手机应用：`cn.zhixing.dashboard`，调试台0.5，已安装并核对APK回读。
- 主控：`r1_gimbal_usbfs_remote`，已备份原程序、烧入并逐字节回读。
- 手机网页含双轴摇杆、位置滑条、幅度选择、回中和停止；P7只允许手动云台及原有读取指令，不开放电机或随机动作。
- 上电输出为0。开启云台后，CH32将脉冲限制在1000～2000微秒，逐步移动；3秒没有保活、USB复位/挂起均停止输出，重连不自动开启。
- 网页数字是主控输出脉冲对应的指令位置，SG90没有返回真实角度。
- USB重连故障依用户要求暂停排查；暂用结束记录后拔插OTG恢复，不能标为根治。

## 先使用云台

1. 断电后拔掉开发板P9和手机到电脑的线。电机电池保持断开。
2. 小手机→OTG→数据线→开发板P7/USBFS；P9留空。开关ON。
3. 水平舵机信号→PA8，俯仰信号→PB0。原接线不变；每只红线→已确认的+5V，棕线→GND。禁止接7.4V电池或3V3。
4. 手机只打开「知行回路调试台」，顶部「连接主控·0.5」→「连接主控并开始记录」，系统USB弹窗允许。
5. 距离/回执更新后返回调试台主页面，点「开启云台」，先选较小幅度，再使用摇杆、回中、停止。
6. 手机独立承担服务，不需要电脑。主力手机访问调试台顶部实时显示的网址，需要与小手机处于能相互通信的同一热点/局域网。

若手机/板子重启、云台卡住或持续抖动、导线被拉紧，立即断开OTG及舵机电源。通信错误时保留提示，拔插恢复后必须重新明确开启；不能把网页按钮状态当成实物已经停止。

两只舵机由小手机OTG供应的实际带载能力尚未验收；软件不能增加USB可提供的电流。若单只正常而双只导致掉电，停止双只供电，另安排5V供电并共地。

## 外接摄像头

摄像头型号识别为UVC `145F:02EC`。使用它的原配完整USB插头，不拆红黑绿白四根线接GPIO。

只有单口转接头时：

`小手机 → OTG → 摄像头原配USB`

这时P7必须暂时断开；云台不能通过这条USB链路同时遥控。在调试台「画面」区域允许相机/USB权限，选640×480、15帧起步，点开启画面。画面与帧号连续更新才算取流成功。

同时连接时需要尚未购入/核验的OTG USB集线器：

```text
小手机 → OTG集线器
          ├─ USB数据线 → CH32 P7/USBFS
          └─ 摄像头原配USB插头
```

开发板P9是WCH-Link调试接口，P7是当前手机通信口，另一个USBHS口没有配置成摄像头转发器。这三个Type-C口不构成USB集线器，不能把摄像头和手机分别插上就期待图像自动转发。

集线器的数据转发、供电及手机OTG兼容性需核验；不把同时接相机+主控或双舵机带载写成已通过。
