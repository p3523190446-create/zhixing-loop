# 车载独立记录：已定方向与实现边界

2026-10-13，依据用户要求：小车离开电脑后，车载设备自行记录；操作者主力手机负责遥控与查看状态；电脑和AI在事后导入记录排查。CH32仍保留最终运动许可，辅助手机不能绕过。

## 最终要记录的内容

| 内容 | 原始记录要求 | 当前电脑原型 |
|---|---|---|
| 指令与回执 | 原始字节、方向、时间、尝试/实际发送及执行回执分别保留 | 已自动记录电脑串口可见字节 |
| 传感器/电机状态 | 原始回传、来源采样时刻、数据年龄、有效位、错误和计数 | 已记录当前回传；未导出的内部数据不在记录内 |
| 摄像画面 | 保留收到的选定模式帧及时间索引，不插帧掩盖缺口 | 需手动开始；队列丢帧计数保留，切模式可续录 |
| 操作与设置 | 遥控输入、模式、阈值、云台、清晰度/FPS与变化时刻 | 已记录当前网页请求及结果，凭据除外 |
| 异常 | 断链/重连/重启、丢帧/丢字节、过期、存储失败、自动停止 | 当前主机异常部分已记录；断电后持久化边界未验收 |
| 版本与时间 | 会话编号、硬件/固件/应用版本、时钟基准与对齐误差 | 电脑单调时钟；未实现设备间同步 |

原始记录与解析显示分开。禁止去重、过滤或改写原始通信来掩盖错误；同一字节流可另生成便于阅读的解释。摄像取流协商到何种模式，就标何种模式；不能将目标帧率或算法估计伪称真实源帧率。已知丢帧/数据未收到/断电尾部未落盘须标明缺口，不能承诺任何故障下全量无损。

## 最终操作流程

1. 车载程序启动即自动建立运行日志，打开摄像画面后自动分段录像；不需要电脑或AI在线、不要求用户记得点录像。
2. 大小/时长到限后继续下一段，保留旧段与分段原因，不静默覆盖。剩余空间不足或写入失败：显著报错并按CH32许可规则停止运动，记录可写入的失败信息。
3. 摄像模式切换、相机/主控重连产生明确事件。恢复后开新段；画面空白期间保留通信日志，主控掉线期间保留摄像及掉线事件。
4. 正常结束写完整性清单；重启识别上次未完成会话，标中断而非完整。用户一键导出原始数据及索引，之后交给AI分析。

这些是最终验收要求，尚未在车载小手机实现。电脑当前录像仍为手动启动、单段到上限停止；手机现有外接相机程序只是预览试验。

## 连接前提与下一步

- 已有三个OTG转换头均单口，不能默认同时接摄像头和主控。优先验证手机→OTG集线器→外接USB摄像头＋经过验证的CH32串口通道；此拓扑目前待核验。
- CH32的三个Type-C分别承担不同功能，不是USB集线器。P9为WCH-Link；P7/USBFS、P6/USBHS用途须由实际固件及枚举决定，不能因为能插就认为能互通。当前固件尚未实现手机直连USBFS通信。
- 整车独立5V供电、手机OTG供电/充电并用能力均待核验。7.4V电池不得直接接5V或USB。不要把已通过电脑USB短试当成车载供电已通过。
- 固件需补导出未发送的驱动串口/传感器错误/复位原因等事件，给出事件序号、原始字段、采样时间及丢失计数。没有上传的数据无法由手机补记录。

下一步先验证手机同时访问相机与主控及独立供电，再迁移记录/遥控。停止条件：通信失联、写入失败、供电不稳、舵机卡住或线缆绷紧即停止运行；不在未验收的链路上开始地面运动。
