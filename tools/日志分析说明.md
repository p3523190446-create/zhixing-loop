# 四列输入记录分析

工具 `analyze_trace.py` 使用 Python 标准库，无第三方依赖。它统计采样记录，便于寻找错误和时间空档；状态判断仍以 C 核心和对应回放程序为准。

可先看 [已经生成的模拟报告](../sim/example_analysis/summary.md)，其中所有数值来自自带人工输入序列。

## 输入与执行

每行格式与 `sim/example_trace.csv` 相同：`time_ms,has_new_sample,valid,distance_mm`。可使用 `#` 注释和 UTF-8 BOM；时间严格递增，重复、倒退、溢出或不完整的行直接报错。重启和计时回绕需分成不同文件。单位是毫秒、毫米，布尔值数值为 0 或 1。

在软件目录运行：

```powershell
# 查看模拟数据的统计，不写文件
python tools/analyze_trace.py sim/example_trace.csv --origin synthetic --firmware software-example

# 保存 JSON 和 Markdown；输出目录必须是新目录，避免覆盖旧证据
python tools/analyze_trace.py sim/example_trace.csv --origin synthetic --firmware software-example --output build/trace-report-01

# 将来真实采集后，声明来源、固件、实验条件
python tools/analyze_trace.py recordings/session-01.csv --origin hardware_declared --firmware board-v1 --conditions '固定障碍板；供电及距离见实验记录' --output build/session-01-report
```

没有系统 Python 时使用 [工具说明](../../比赛备案/06-工具使用说明.md) 中已确认的解释器路径。第三条中的记录文件目前不存在，只是未来命令格式，不是已采集数据。

## 结果如何解释

| 指标 | 能说明 | 不能说明 |
| --- | --- | --- |
| 有效/无效新样本数 | 日志中驱动分别报告了多少次 | 测量值真实准确、障碍物都被识别 |
| 无效比例 | 无效新样本数除以所有新样本数 | 整机失败率、漏报率、可靠性 |
| 最大相邻记录间隔 | 提供的日志行之间最大时间空档 | 一定是传感器卡住，也可能日志漏行 |
| 最大有效样本间隔 | 两次有效测量声明之间的空档 | 记录末尾的停更时间；该项另记 |
| 末次有效样本至末行 | 有记录覆盖的尾部空档 | 文件结束后的系统行为 |
| 距离最小/中位/最大值 | 有效读数的范围 | 相对尺测真值的误差与精度 |

没有有效样本时距离统计为 `null/不可计算`；没有新样本时比例也为未知，不填 0。单行记录不能推断采样间隔。`available=false` 时会忽略该行的 valid 和距离，和 C 核心语义一致。

报告记录原文件 SHA-256、声明的固件版本和条件。`hardware_declared` 只表示操作者声明来源，工具不能从文本证明它出自真实板卡。实际动作、尺测真值、输出时间戳和原始传感器状态仍需另存。

## 建议的实板记录最小组合

```text
recordings/
  session-01.csv            # 供工具分析/回放的四列原始输入
  session-01-context.md     # 固件、供电、物体、动作、错误与来源说明
  session-01-raw.txt        # 原始状态码/串口日志，保留错误
```

日志发送应尽量不改变主循环时序；是否丢行与实际循环周期须测量。不要因日志太密就丢掉失败行；需要降采样时先保留完整原件，写清转换过程。

下一步：到板后先采一小段“固定远处→移近→恢复”，用 T08 对照原始日志与状态。停止条件：来源、单位、固件或时间顺序不明时先纠正记录，不拿统计报告证明实物完成。
